# 故障模式：为什么智能体会出错

> MASFT（伯克利，2025）在三个类别中分类了 14 种多智能体故障模式。微软的故障模式分类文档记录了现有 AI 故障如何在智能体环境中放大。行业现场数据收敛于五种 recurring 模式：幻觉动作、范围蔓延、级联错误、上下文丢失、工具误用。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置知识：** Phase 14 · 05（自我完善与 CRITIC），Phase 14 · 24（可观测性）
**时间：** 约 60 分钟

## 学习目标

- 列举 MASFT 的三个故障类别及每个类别中至少四种具体模式。
- 解释为何智能体故障会放大现有 AI 故障模式（偏见、幻觉）。
- 描述五种行业 recurring 模式及其缓解措施。
- 实现一个标准库检测器，为智能体轨迹打上故障模式标签。

## 问题所在

团队发布的智能体在 90% 的轨迹上表现良好。那 10% 的故障并非随机噪声——它们落入少量 recurring 类别中。一旦你能命名它们，你就能监控并修复它们。

## 概念

### MASFT（伯克利，arXiv:2503.13657）

多智能体系统故障分类法。14 种故障模式聚类为 3 个类别。标注者间 Cohen's Kappa 系数为 0.88——类别之间可可靠区分。

核心主张：故障是多智能体系统中的根本设计缺陷，而非通过更好的基础模型可以修复的 LLM 局限性。

### 微软智能体 AI 系统故障模式分类

- 现有 AI 故障（偏见、幻觉、数据泄露）在智能体环境中会被放大。
- 新的故障源于自主性：规模化的意外动作、工具误用、任务偏离。
- 这篇白皮书是智能体产品的风险登记册。

### 表征智能体 AI 中的故障（arXiv:2603.06847）

- 故障源于编排、内部状态演化和环境交互。
- 不仅仅是"糟糕的代码"或"糟糕的模型输出"。

### LLM 智能体幻觉综述（arXiv:2509.18970）

两种主要表现形式：

1. **遵循指令偏差**——智能体未遵循系统提示。
2. **长程上下文误用**——智能体遗忘或错误应用了前面轮次中的上下文。

子意图错误：遗漏（跳过步骤）、冗余（重复步骤）、无序（步骤顺序错误）。

### 五种行业 recurring 模式

Arize、Galileo、NimbleBrain 2024-2026 年现场分析达成共识：

1. **幻觉动作。** 智能体调用了不存在的工具或捏造了参数。
2. **范围蔓延。** 智能体将任务范围扩展到用户要求之外（创建额外 PR、发送额外邮件）。
3. **级联错误。** 一个错误调用触发下游连锁效应。一个幽灵 SKU 的幻觉触发了四次 API 调用——造成多系统事故。
4. **上下文丢失。** 长周期任务遗忘早期轮次的约束条件。
5. **工具误用。** 用错误的参数调用正确的工具，或完全调用错误的工具。

级联是致命问题。智能体无法区分"我失败了"和"任务不可能完成"，经常在 400 错误上幻觉出一条成功消息来闭环。

### 缓解措施：每步设置检查门

在推理链的每一步设置自动化验证检查门，针对环境状态核查事实依据。具体措施：

- 每步安全分类器（第 21 课）。
- 工具调用参数校验（第 6 课）。
- 交叉核查检索内容与实际事实（第 5 课，CRITIC）。
- 通过重新探测状态来检测成功幻觉（文件是否真的被创建了？）。

### 故障监控的常见误区

- **仅标记崩溃。** 大多数智能体故障产生看起来有效的输出。需要内容级别的检查。
- **没有基线。** 漂移检测需要最后已知正常状态；没有基线你就无法说"情况在恶化"。
- **过度告警。** 每次故障都触发一次通知。需要聚类和限流。

## 构建它

`code/main.py` 实现了一个标准库故障模式标签器：

- 覆盖五种模式的合成轨迹数据集。
- 每种模式的检测函数（工具调用、输出、重复动作的模式签名）。
- 一个为每条轨迹打标签并报告模式分布的标签器。

运行它：

```
python3 code/main.py
```

输出：每条轨迹的标签 + 聚合分布，这是对 Phoenix 轨迹聚类效果的廉价复现。

## 如何使用

- **Phoenix** 用于生产环境漂移聚类（第 24 课）。
- **Langfuse** 用于会话回放和标注。
- **自定义** 用于可观测平台无法检测的领域特定签名。

## 交付物

`outputs/skill-failure-detector.md` 生成面向你所在领域的定制故障模式检测器，并接入轨迹存储。

## 练习

1. 添加一个"成功幻觉"检测器：智能体返回成功但目标状态未改变。
2. 对你开发的一个产品标注 100 条真实轨迹。哪种模式占主导？修复它的成本是多少？
3. 实现"级联半径"指标：给定步骤 N 处的故障，它影响了多少下游步骤？
4. 阅读 MASFT 的 14 种故障模式。选择三种适用于你产品的模式，编写检测器。
5. 将一个检测器接入 CI 任务：如果 >=5% 的轨迹标记了某模式，则构建失败。

## 关键术语

| 术语 | 人们所说的 | 实际含义 |
|------|-----------|---------|
| MASFT | "多智能体故障分类法" | 伯克利 14 模式分类 |
| 级联错误 | "连锁故障" | 一个早期错误传播经过 N 步 |
| 上下文丢失 | "忘记约束" | 长周期轮次丢弃早期轮次的事实 |
| 工具误用 | "工具/参数错误" | 调用有效但用法错误 |
| 成功幻觉 | "伪造完成" | 智能体在 400 错误上声称成功；状态未变 |
| 范围蔓延 | "越界" | 智能体做了超出要求的事 |
| 遵循指令偏差 | "不服从" | 忽略系统提示或用户约束 |
| 子意图错误 | "计划缺陷" | 计划执行中的遗漏、冗余、无序 |
