# 编排模式：主管-工人、群体、层级

> 2026年的框架中反复出现四种编排模式：主管-工人、群体/对等、层级、辩论。Anthropic 的建议是："根据你的需求构建合适的系统。"从简单开始；只有当单个智能体加上五种工作流模式仍不足时，才增加拓扑结构。

**类型：** 学习 + 实践
**语言：** Python (stdlib)
**前置条件：** 第 14 阶段 · 12（工作流模式）、第 14 阶段 · 25（多智能体辩论）
**时间：** 约 60 分钟

## 学习目标

- 说出四种反复出现的编排模式及其适用场景。
- 描述 LangChain 2026 年的建议：通过工具调用实现监督 vs 使用主管库。
- 解释 Anthropic 的"构建合适的系统"原则以及如何用它来指导拓扑选择。
- 在标准库中对模拟 LLM 实现所有四种模式。

## 问题所在

团队往往在真正需要之前就急于采用"多智能体"方案。四种模式在不同框架中反复出现；一旦你能命名它们，就能选对模式——或者直接跳过拓扑设计。

## 概念解析

### 主管-工人

- 一个中心路由 LLM 将任务分派给专业智能体。
- 决策逻辑：循环返回自身、交给专家、终止。
- 专家之间不直接通信；所有路由都经过主管。

框架示例：LangGraph `create_supervisor`、Anthropic orchestrator-workers、CrewAI Hierarchical Process。

**2026 年 LangChain 建议：** 通过直接工具调用实现监督，而非使用 `create_supervisor`。这样可以更精细地控制上下文工程——你可以精确决定每个专家能看到什么。

### 群体 / 对等

- 智能体通过共享工具表面直接交接任务。
- 没有中心路由器。
- 相比主管模式延迟更低（跳数更少）。
- 更难推理分析（缺乏单一控制点）。

框架示例：LangGraph swarm 拓扑、OpenAI Agents SDK 的手递手功能（当所有智能体都能相互交接时）。

### 层级

- 主管管理子主管，子主管管理工人。
- 在 LangGraph 中实现为嵌套子图；在 CrewAI 中实现为嵌套团队。
- 可扩展到大规模智能体集群，代价是运维复杂度上升。

何时需要：当单个主管的上下文预算无法容纳所有专家的描述时。

### 辩论

- 并行提案者 + 迭代交叉批判（第 25 课）。
- 本质上不是编排——更像是验证——但在框架中常表现为一种拓扑选择。

### 自主团队 vs 确定性流程

CrewAI 正式定义了两种部署模式：

- **Flow**：用于确定性事件驱动自动化（推荐的生产环境起点）。
- **Crew**：用于自主角色协作。

这与上述四种模式正交，但可映射到拓扑：Flow 通常是主管或层级模式；Crew 通常是带 LLM 路由的主管模式。

### Anthropic 的建议

"LLM 领域的成功不在于构建最复杂的系统，而在于构建适合你需求的系统。"

决策顺序：

1. 单智能体 + 工作流模式（第 12 课）——从这里开始。
2. 主管-工人——当你有 2-4 个专家时。
3. 群体——当延迟比推理清晰度更重要时。
4. 层级——仅当主管上下文预算不足时。
5. 辩论——当准确性比成本更重要时。

### 这些模式常见的错误用法

- **先定拓扑再想问题。** "我们需要多智能体"——但还没明确多智能体能解决什么问题。
- **群体中的来回跳转。** A -> B -> A -> B。使用跳数计数器。
- **虚假层级。** 因为"企业级"而设三层，实际只有两个团队。应当合并。

## 实践构建

`code/main.py` 在标准库中对模拟 LLM 实现了所有四种模式：

- `Supervisor` — 中心路由器。
- `Swarm` — 带直接交接的对等模式。
- `Hierarchical` — 主管之上的主管。
- `Debate` — 并行提案者 + 批判者。

每种模式处理相同的三个意图任务（退款 / 故障 / 销售）。追踪形状各不相同。

运行方式：

```
python3 code/main.py
```

输出：每种的追踪记录 + 操作计数。主管模式最清晰；群体模式最短；层级模式最深；辩论模式成本最高。

## 实际应用

- **LangGraph** 用于主管和层级模式（嵌套子图）。

- **CrewAI Flow** 用于生产环境的确定性流程。
- **自定义实现** 用于辩论或需要精确控制时。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|-----------|---------|
| 主管-工人 | "路由器 + 专家" | 中心 LLM 分派给专家；专家之间不通信 |
| 群体 | "对等网络" | 通过共享工具直接交接；无中心路由器 |
| 层级 | "主管之上的主管" | 用于大规模集群的嵌套子图 |
| 辩论 | "提案者 + 批判者" | 并行提案，交叉批判（第 25 课） |
| 基于工具调用的监督 | "不用库的主管" | 通过直接工具调用实现主管以控制上下文 |
| Crew | "自主团队" | CrewAI 的角色协作模式 |
| Flow | "确定性工作流" | CrewAI 的事件驱动生产模式 |
