# 流水线并行与气泡分析

> 张量并行将矩阵乘法拆分到多个 rank 上。流水线并行将模型拆分到多个 rank 上，每个 rank 负责一个 stage。微批次（microbatch）沿流水线流动。流水线开始和结束时的空闲时间就是气泡；减少气泡是整个工艺的核心。

**类型：** 构建
**语言：** Python
**前置要求：** 阶段 19 Track C 课程 42-49
**时间：** 约 90 分钟

## 学习目标

- 将顺序模型拆分为 N 个 stage，并在 N 个 rank 上模拟前向流水线。
- 使用 GPipe 调度（前向填充，然后反向）将 M 个微批次通过流水线，并计算气泡比例。
- 与 Megatron-LM 和 PipeDream 使用的交错 1F1B 调度相比气泡。
- 为 stage 分配方式辩护：每个 stage 的计算均衡比每个 stage 的参数均衡更重要。

## 问题背景

一个 70B 参数的模型在 fp16 下仅参数就需要 140 GB 显存，没有任何消费级 GPU 能装下。ZeRO-3 将参数分片到各 rank，但仍需要每个 rank 对每一层做全聚合（allgather），每层产生 log(N) 次通信跳数。流水线并行采取不同路线：将模型切成 N 个 stage，每个 rank 放一个 stage。第 0 层的 forward 在 rank 0 上完成，将激活张量传递给 rank 1；rank 1 执行第 2 层并传给 rank 2，依此类推。反向传播沿相反方向流动。内存线性下降，因为每个 rank 只持有单个 stage；计算是串行的，这就是气泡问题所在。

气泡是流水线开始时的空闲时间（等待第一个微批次到达最后一个 stage）和结束时的空闲时间（等待最后一个微批次回流）。有 M 个微批次和 N 个 stage 时，每 stage 的气泡比例为 (N-1)/(M+N-1)。当 M=8、N=4 时为 27%。当 M=64、N=4 时为 4.5%。当你每个 step 有足够多的微批次时，气泡会缩小，这意味着每个微批次的 batch size 较小，这也是驱动微批次设计的关键约束。

### GPipe 调度

先将全部 M 个微批次前向填充流水线，再开始反向传播；然后以反向顺序排空。来自每个微批次的激活必须在反向之前保存，因此内存随 M 线性增长。前向需要 M+N-1 个周期，反向同样需要 M+N-1 个周期。每 stage 的有效工作量为 2M 个周期，每 stage 的气泡为 2(N-1) 个周期。当每次前向和反向耗时为 1 个单位时，气泡比例为 (N-1)/(M+N-1)。选择 M 远大于 N 可以掩盖气泡。

### 1F1B 调度

交错调度：当一个微批次的前向到达最后一个 stage 时，立即开始其反向传播并让它流回。调度在每个 stage 上交替执行一次前向和一次反向。气泡仍为 N-1，但激活内存受流水线深度约束，而非微批次数量。生产环境流水线使用 1F1B（Megatron、PipeDream）。本教程先实现 GPipe 因为它更简单，1F1B 作为练习。

### 为什么每个 stage 计算均衡更重要

如果 stage 0 耗时 50 ms 而 stage 1 耗时 100 ms，每个周期都被 stage 1 限制。其他 stage 每周期空闲 50 ms，等待 stage 1 释放。按参数数量均衡是错误的维度：transformer 的计算主要由每层的注意力加上 MLP 决定，embedding 层有大量参数但计算量很小。stage 分配应使每个 stage 的 FLOPs 均衡，而非权重数量均衡。

### 微批次与批次

流水线运行 M 个大小为 B 的微批次。有效 batch size 为 M*B。流水线 step 结束时的梯度是合并后 M*B 个样本上的梯度。气泡比例取决于 M；优化器看到的是 M*B。调整 M 意味着在气泡（M 越大气泡越小）与每微批次内存（GPipe 下 M 越大激活内存越高）之间权衡。

## 生产中的实践模式

有三种模式将流水线并行硬化到可交付水平。

**激活检查点与流水线配合。** GPipe 上有 M 个微批次在飞行中，激活内存是一个微批次的 M 倍。激活检查点在反向时重算前向，以计算换内存；两者的结合使长序列下的流水线变得可行。

**stage 平衡靠测量而非假设。** 生产团队会运行分析阶段，测量目标硬件上每层的实际计算量（FLOPs 和墙钟时间），然后根据该测量结果分区。Megatron-LM 的 `--num-layers-per-stage` 标志接受一个列表，允许在每层成本不同的 stage 间进行不均匀的层数分配。

**发送/接收调度必须避免死锁。** 如果一个流水线的所有 stage 都先发送再接收，会在通信链路上死锁。标准修复是交错调度：偶数 rank 的 stage 先发后收，奇数 rank 的 stage 先收后发。本教程显式调度 rank，以便观察该模式。

## 使用

生产模式：

- **Megatron-LM。** 大规模流水并行的参考实现。使用 1F1B 并支持张量并行 + 流水线并行 + 数据并行组合。
- **DeepSpeed Pipeline。** 与 ZeRO 集成；ZeRO-1 + 流水线是最大开源模型的常见组合。
- **PyTorch Pipe。** PyTorch 原生流水线封装，基于 `torch.distributed.pipeline.sync.Pipe` 构建。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|------------|----------|
| 流水线 | "沿深度方向的模型并行" | 每个 rank 一个 stage，激活沿 stage 流动 |
| 气泡 | "流水线空闲时间" | 开始和结束时 (N-1) 个步骤，某些 stage 无工作 |
| 微批次 | "批次的切片" | 一次前向/反向的单位；气泡随 M 增大而缩小 |
| GPipe | "先填后排空" | 所有 M 次前向在任意反向之前；高激活内存 |
| 1F1B | "交错调度" | 每个 stage 一次前向一次反向；有界激活内存 |
