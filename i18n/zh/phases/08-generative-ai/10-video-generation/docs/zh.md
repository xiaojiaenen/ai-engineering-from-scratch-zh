# 视频生成

> 图像是一个二维张量，视频是一个三维张量。理论相同，但计算难度高出 10-100 倍。OpenAI 的 Sora（2024 年 2 月）证明了其可行性。到 2026 年，Veo 2、Kling 1.5、Runway Gen-3、Pika 2.0 和 WAN 2.2 已能从文本以 1080p 生成生产级视频——开源权重栈（CogVideoX、HunyuanVideo、Mochi-1、WAN 2.2）落后约 12 个月。

**类型：** 构建
**语言：** Python
**前置知识：** Phase 8 · 07（潜在扩散）、Phase 7 · 09（ViT）、Phase 8 · 06（DDPM）
**时间：** 约 45 分钟

## 问题所在

一段 10 秒、1080p、24fps 的视频包含 240 帧，每帧为 1920×1080×3 像素。这相当于每条片段约 1.5 GB 的原始数据。像素空间扩散不可行。你需要：

1. **时空压缩。** 一个能编码视频（而非逐帧）的 VAE，将其压缩为时空 patch 序列。
2. **时间连贯性。** 帧之间需要共享内容、光照和物体身份。模型必须能建模运动。
3. **算力预算。** 同样模型规模下，视频训练比图像贵 10-100 倍。
4. **条件控制。** 文本、图像（首帧）、音频，或另一段视频。大多数生产级模型同时支持四种条件输入。

解决这一问题的架构是将**扩散 Transformer（DiT）**应用于时空 patch，在海量（提示词、字幕、视频）数据集上训练。扩散损失与第 06 课相同。

## 核心概念

![视频扩散：patchify、DiT、解码](../assets/video-generation.svg)

### Patchify

用 3D VAE 对视频进行编码（学习到的时空压缩）。潜变量形状为 `[T_latent, H_latent, W_latent, C_latent]`。将其分割为大小为 `[t_p, h_p, w_p]` 的 patch。对于 Sora 风格模型，`t_p = 1`（每帧独立）或 `t_p = 2`（每两帧一组）。一段 10 秒 1080p 视频会被压缩为约 20,000-100,000 个 patch。

### 时空 DiT

Transformer 处理展开的 patch 序列。每个 patch 带有 3D 位置嵌入（时间 + y + x）。注意力通常采用因式分解方式：

- **空间注意力：** 单帧内各 patch 之间的注意力。
- **时间注意力：** 相同空间位置跨帧的注意力。
- **完整 3D 注意力：** 成本是前两者的 16-100 倍，仅在低分辨率或研究中使用。

### 文本条件控制

与大型文本编码器进行交叉注意力（Sora 使用 T5-XXL，CogVideoX-5B 也使用 T5-XXL）。长提示词很重要——Sora 训练集中有 GPT 生成的密集重标注，平均每片段 200 个 token。

### 训练

在时空潜变量上使用标准扩散损失（ε 或 v 预测）。数据：网络视频 + 约 1 亿条精心挑选的片段 + 合成文本字幕。算力：即使是小型研究实验也需要 10,000+ GPU 小时；Sora 级别则需要 100,000+。

## 动手实现

`code/main.py` 模拟了核心时空 DiT 思想：对小规模合成视频进行 patchify，添加逐 patch 位置嵌入，然后用 transformer 风格注意力对序列整体去噪。不使用 numpy，纯 Python 实现。我们展示即使在一维场景中，相邻帧 patch 共享去噪器和位置嵌入时，时间连贯性也会自然涌现。

### 步骤 1：patchify 合成的一维"视频"

```python
def make_video(T_frames=8, rng=None):
    # 一维"视频"是跟随平滑轨迹的序列值
    base = rng.gauss(0, 1)
    return [base + 0.3 * t + rng.gauss(0, 0.1) for t in range(T_frames)]
```

### 步骤 2：每帧的位置嵌入

```python
def pos_embed(t, dim):
    return sinusoidal(t, dim)
```

### 步骤 3：去噪器看到整个序列

不逐帧独立去噪，我们的微小网络将所有帧的值与其位置嵌入拼接，联合预测所有帧的噪声。

### 步骤 4：时间连贯性测试

训练完成后采样一段视频。测量帧间差分。如果模型学到了时间结构，差分将小于逐帧独立采样的结果。

## 常见陷阱

- **逐帧独立采样 = 闪烁。** 如果对各帧分别运行图像扩散，输出会闪烁，因为每帧的噪声相互独立。视频扩散通过注意力或共享噪声耦合帧来解决这一问题。
- **朴素 3D 注意力 = 显存溢出。** 对 10 秒 1080p 潜变量做完整 3D 注意力涉及数千亿次操作。需因式分解为空间 + 时间注意力。
- **数据字幕质量比规模更重要。** Sora 相比前期工作的主要升级是在约 10 倍更详细的字幕上训练（GPT-4 重新标注片段）。OpenAI 技术报告对此有明确说明。
- **首帧条件控制。** 大多数生产级模型还接受图像作为首帧。这是"图像转视频"模式，训练时也包含此变体。
- **物理漂移。** 长片段（>10 秒）会累积细微的不一致。滑动窗口生成 + 关键帧锚定可缓解这一问题。

## 生产备注：视频潜变量是内存带宽问题

一段 10 秒、1080p、24fps 的片段包含 240 帧 × 1920 × 1080 × 3 ≈ 1.5 GB 原始像素。经过 4 倍视频 VAE 压缩（`2× 空间 × 2× 时间`）后，潜变量约 100 MB/请求。将其通过时空 DiT 运行 30 步（batch=1），每步需在 HBM 间传输约 3 GB——内存带宽而非 FLOPs 才是瓶颈。

三个来自生产推理文献生产推理章节的关键调参项：

- **DiT 跨设备张量并行（TP）。** 文本转视频模型通常 ≥10B 参数。TP=4 跨 4 张 H100 是标准配置；PP=2 × TP=2 用于 405B 级模型。每步延迟随 TP 线性下降（受 all-reduce 墙限制）。
- **帧级批处理 = 连续批处理。** 生成时，视频可概念化为由注意力链接的帧批次。连续批处理（in-flight scheduling）适用：当模型架构支持滑动窗口生成时，在返回帧 `t-1` 的同时开始渲染帧 `t+1`。
- **片段级 Prefill 缓存。** 对于图像转视频，首帧条件控制类似于 LLM 的 prompt prefill：计算一次，跨时间解码器传递复用。这本质上是视频的 KV 缓存。
