# 谈判与议价

> 智能体就资源、价格、任务分配和条款进行协商。2026年的基准集非常明确：NegotiationArena（arXiv:2402.05863）显示LLM可以通过人格操纵（"绝望"）将收益提升约20%；"Measuring Bargaining Abilities"（arXiv:2402.15813）表明买方比卖方更难，且规模并不能解决问题——它们的 **OG-Narrator**（确定性报价生成器 + LLM叙述者）将成交率从26.67%提升至88.88%；大规模自主谈判竞赛（arXiv:2503.06416）运行了约18万次谈判，发现**隐藏思维链**的智能体通过向对手隐藏推理过程而获胜；Bhattacharya等人2025年关于哈佛谈判项目指标的研究将Llama-3评为最有效，Claude-3最具攻击性，GPT-4最公平。本课程实现Contract Net协议（FIPA祖先，课程02），连接LLM风格的买方/卖方，运行OG-Narrator风格的分解，并衡量每种结构性选择对成交率的影响。

**类型：** 学习 + 构建
**语言：** Python (stdlib)
**前置条件：** 阶段16 · 02（FIPA-ACL遗产）、阶段16 · 09（并行蜂群网络）

## 问题

两个智能体需要就价格达成一致。仅凭纯语言提示，2024-2026年的LLM成交率令人惊讶地低（arXiv:2402.15813中紧密参数化的议价场景约为27%）。规模无法解决这个问题：GPT-4在议价方面的结构性能力并不优于GPT-3.5；它在议价的*语言*方面更好。

根本问题在于LLM混淆了两项工作——决定报价和叙述报价。OG-Narrator将这两者分离：确定性报价生成器计算数值动作；LLM仅负责叙述。成交率跃升至约89%。

这呼应了一个经典的多智能体发现：将机制与通信层解耦能够获胜。Contract Net协议（FIPA，1996；Smith，1980）是参考的任务市场机制。将LLM接入叙述槽位，你就得到了一个现代LLM驱动的任务市场。

## 概念

### Contract Net，一段话概括

Smith的1980年Contract Net协议：一个**管理者**广播**提案邀请（cfp）**；**投标者**响应包含报价的**提案（propose）**消息；管理者选择获胜者并向获胜者发送**接受提案（accept-proposal）**，向失败者发送**拒绝提案（reject-proposal）**。获胜者执行工作。可选消息：**拒绝（refuse）**（投标者拒绝报价）。FIPA将其编撰为`fipa-contract-net`交互协议。

### 为何OG-Narrator胜出

"Measuring Bargaining Abilities of Language Models"（arXiv:2402.15813）观察到：

- LLM经常违反议价规则（在毫无意义的价格上报价、忽视另一方的ZOPA）。
- 锚定效果差（接受糟糕的首次报价、以象征性而非战略性金额反报价）。
- 仅靠规模无法解决这些问题。更大的模型能生成更合理可信的语言，但存在类似的策略性错误。

OG-Narrator分解如下：

```
           ┌──────────────────┐        ┌──────────────────┐
  state  → │ offer generator  │ price → │  LLM narrator    │ → message
           │  (deterministic) │        │  (writes the     │
           │                  │        │   human-style    │
           └──────────────────┘        │   accompaniment) │
                                       └──────────────────┘
```

报价生成器是经典的谈判策略：Rubinstein议价模型、Zeuthen策略或价格上的简单以牙还牙。LLM负责叙述。消息包含确定性价格和自然语言框架。

成交率跃升的原因在于：
- 价格保持在议价区间内。
- 锚点是策略性的，而非情绪化的。
- LLM做它擅长的事：写作。

### NegotiationArena发现

arXiv:2402.05863提供了规范的基准。主要发现：

- LLM采用人格（"我星期五前必须卖掉这个"）可以将收益提升约20%——人格操纵是一种真实战术。
- 公平/合作型智能体被对抗型智能体利用；防御需要显式的反姿态。
- 对称配对在约40%的基准场景中收敛于不公平的结果。

这不是"LLM是糟糕的谈判者"。而是"LLM谈判时过于像人类，包括那些容易被利用的部分"。

### 思维链隐藏

大规模自主谈判竞赛（arXiv:2503.06416）运行了约18万次涉及多种LLM策略的谈判。获胜者向对手隐藏其推理：

- 如果一个智能体将"我只会到75美元；我的保留价格是70美元"打印到公开可见的便笺中，对手会读到它。
- 获胜者私下计算策略；输出通道仅包含报价和最低限度的叙述。

这是经典博弈论在2026年的回响（Aumann 1976关于理性与信息）：暴露私人估值会损失收益。LLM不会直觉到这一点，并乐意在成为对手可见的推理轨迹中键入其保留价格。

工程要点：将私有便笺上下文与公共消息上下文分离。这不是可选的。

### Bhattacharya等人2025年——模型排名

在哈佛谈判项目指标上（原则性谈判、BATNA尊重、利益互惠）：

- **Llama-3** 在达成交易方面最有效（成交率 + 收益）。
- **Claude-3** 是最具攻击性的谈判者（高锚点、后期让步）。
- **GPT-4** 是最公平的（配对间收益方差最小）。

这是2025年的快照。重点不在于哪个模型在2026年4月胜出——而在于不同基础模型具有持久的谈判风格。异构集成（课程15）将此作为多样性来源。

### 通过Contract Net + LLM进行任务分配

Contract Net在现代LLM多智能体中的重新利用：

1. 管理者智能体将任务分解为单元。
2. 向工作智能体广播包含任务描述的`cfp`。
3. 每个工作智能体返回报价：`(price, eta, confidence)`，其中price可以是token、计算单元或美元。
4. 管理者选择获胜者（单个或多个，取决于任务）并进行分配。
5. 被拒绝的工作智能体可以投标其他任务。

这扩展到100个工作智能体以上时表现良好，因为协调是广播-响应式，而非同步聊天。已用于生产：Microsoft Agent Framework的编排模式、某些LangGraph实现。

### LLM利益相关者交互式谈判

NeurIPS 2024（https://proceedings.neurips.cc/paper_files/paper/2024/file/984dd3db213db2d1454a163b65b84d08-Paper-Datasets_and_Benchmarks_Track.pdf）引入了多方评分游戏，具有**秘密评分**和**最低接受阈值**。每个利益相关者都有私人效用；LLM必须从消息中推断它们。这是两方议价向N方联盟形成的推广。适用于具有异构工作智能体能力的生产任务市场。

### 叙述vs机制规则

在所有2024-2026年谈判基准中，一致的工程规则是：

> 让LLM叙述。不要让LLM计算报价。

如果报价需要是一个数字（价格、ETA、数量），从谈判状态确定性生成，让LLM生成框架。如果报价需要是一个提案结构（任务分解、角色分配），让LLM起草，但在发送前对照架构验证并进行约束检查。

## 构建

`code/main.py`实现：

- `ContractNetManager`、`ContractNetTask`、`Bid`——管理者 + 投标者、广播cfp、收集提案、分配。
- `og_narrator_bargain(state, rng)`——OG-Narrator买方：确定性Zeuthen式向中点让步。
- `seller_response(state, rng)`——确定性卖方反报价策略（两种风格的结构性基准事实）。
- `naive_llm_bargain(state, rng)`——模拟全LLM谈判者：以高方差选择价格，经常在ZOPA之外。
- 测量：每次试验使用新采样的保留价格，进行1000次试验的成交率。

运行：

```
python3 code/main.py
```

预期输出：naive-LLM成交率约65-75%；OG-Narrator成交率约85-95%；15-25个百分点的差距体现了将报价生成与叙述解耦的结构性优势。加上一个三个投标者和一个任务的Contract Net任务市场分配示例。

## 使用

`outputs/skill-bargainer-designer.md`设计了一个议价协议：谁生成报价（确定性或LLM）、谁叙述、私有便笺如何与公共消息分离、以及如何监控成交率。

## 交付

生产级议价清单：

- **分离便笺。** 私有状态绝不能到达对手上下文。这是不可协商的。
- **确定性报价生成。** 价格、数量、ETA：计算，不要提示。
- **对照架构验证所有传入报价。** 在协议边界拒绝超出ZOPA的报价。
- **限制轮次。** 最多3-5轮；僵持时升级到调解人。
- **持续测量成交率和收益方差。** 下降的成交率是一个症状——通常是提示漂移或对手方攻击。
- **记录所有被拒绝的提案及其确定性理由。** 对于Contract Net管理者，失败的投标者需要理解原因。

## 练习

1. 运行`code/main.py`。确认OG-Narrator在成交率上击败naive-LLM。差距多大？
2. 实现**基于人格的收益提升**（arXiv:2402.05863）——买方在叙述中采用"急于本周购买"的人格，报价生成器不变。成交率或收益是否变化？
3. 实现思维链**隐藏**：维护一个不传递给对手的私有便笺字符串。如果你意外泄露它（通过交换通道进行模拟），会发生什么？
4. 将Contract Net扩展到带保留价的N投标者拍卖。当所有 bids 都超过保留价时，管理者如何决定最低价格与最高质量之间的选择？你选择哪种分配规则，为什么？
5. 阅读Bhattacharya等人2025年关于哈佛谈判项目指标的研究。实现两种不同风格（攻击性vs公平）的谈判者。在对称和非对称配对下测量收益方差。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| Contract Net | "任务市场" | Smith 1980，FIPA 1996。cfp + propose + accept/reject。规范的任务市场。 |
| ZOPA | "可能协议区" | 买方最高价与卖方最低价的重叠区。超出该区的报价无法成交。 |
| BATNA | "协议最佳替代方案" | 如果本次交易失败，你的后备方案。设定你的保留价格。 |
| OG-Narrator | "报价生成器 + 叙述者" | 解耦：确定性报价、LLM叙述。 |
| Zeuthen策略 | "风险最小化让步" | 基于风险限制的古典报价生成器。 |
| Rubinstein议价 | "交替报价均衡" | 带折扣的无限期议价博弈论模型。 |
| CoT隐藏 | "隐藏你的推理" | arXiv:2503.06416中的获胜者保留私有便笺；公共通道仅显示报价。 |
| 人格操纵 | "情绪姿态" | arXiv:2402.05863：~20%的收益增益来自绝望/紧迫感人格。 |
