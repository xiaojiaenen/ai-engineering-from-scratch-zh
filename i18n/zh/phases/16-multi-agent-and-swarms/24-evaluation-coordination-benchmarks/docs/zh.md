# 评估与协调基准

> 五个 2025-2026 年的基准测试覆盖了多智能体评估领域。**MultiAgentBench / MARBLE**（ACL 2025，arXiv:2503.01935）评估星型/链型/树型/图型拓扑，并引入里程碑 KPI；**图型拓扑最适合研究场景**，认知规划可额外提升约 3% 的里程碑达成率。**COMMA** 评估多模态非对称信息协调；包括 GPT-4o 在内的前沿模型甚至难以超越随机基线。**MedAgentBoard**（arXiv:2505.12371）涵盖四类医疗任务，且经常发现多智能体并不优于单 LLM。**AgentArch**（arXiv:2509.10769）对结合工具使用 + 记忆 + 编排的企业智能体架构进行基准测试。**SWE-bench Pro**（[arXiv:2509.16941](https://arxiv.org/abs/2509.16941)）包含来自 41 个仓库的 1865 个问题，覆盖商业应用、B2B 服务和开发者工具；前沿模型在 Pro 上得分约 23%，而在 Verified 上得分 70%+ —— 这是对数据污染的现状检验。Claude Opus 4.7（2026年4月）在 Pro 上的报告得分为 **64.3%**（使用了显式智能体团队协作，但 Anthropic 尚未发布官方数据源 —— 请视为初步结果）；Verdent（智能体脚手架）在 Verified 上达到 **76.1% pass@1**（[Verdent 技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）。**AAAI 2026 Bridge Program WMAC**（https://multiagents.org/2026/）是 2026 年的社区核心焦点。本课程基于 MARBLE 的指标，运行拓扑与指标扫描，并确立"仅仅通过 SWE-bench Verified 并不能证明泛化能力"这一规则。

**类型：** 学习
**语言：** Python（标准库）
**前置要求：** 第 16 阶段 · 15（投票与辩论拓扑），第 16 阶段 · 23（失败模式）
**时间：** 约 75 分钟

## 问题

当一篇论文声称"我们的多智能体系统更好"时，真正的问题在于：比什么更好？在什么上更好？如何衡量？2023-2024 年的多智能体评估处于混乱状态 —— 每个人都选择自己的指标、自己的基线和自己的任务集。2025-2026 年的基准测试引入了规范。

没有共享基准，你就无法有意义地比较两个多智能体系统。更糟的是，没有独立测试基准，前沿模型就会产生数据污染。SWE-bench Verified 到 2025 年年中已在训练语料中部分被污染；前沿分数膨胀；Pro 被设计为不受污染的现实检验。

本课程枚举五个规范的 2026 基准测试，明确每个基准测量的内容，并教你如何以怀疑态度解读基准声明。

## 概念

### MultiAgentBench (MARBLE) — ACL 2025

arXiv:2503.01935。评估四种协调拓扑（星型、链型、树型、图型）在研究、编码和规划任务上的表现。基于里程碑的 KPI 追踪部分进展，而非仅关注最终成功。

测量结果：

- **图型**拓扑最适合研究场景；支持任意对任意的批评。
- **链型**最适合逐步优化的编码任务。
- **星型**最适合快速的事实整合。
- **协调开销**在图型拓扑超过约 4 个智能体后出现。
- **认知规划**在各拓扑上可额外提升约 3% 的里程碑达成率。

适用场景：当你想要以同样标准比较协调拓扑时。MARBLE 仓库（https://github.com/ulab-uiuc/MARBLE）提供了评估器。

### COMMA — 多模态非对称信息

涵盖智能体具有不同观察模态且必须在不完整信息共享的情况下协调的任务。报告的结果令人不安：包括 GPT-4o 在内的前沿模型在 COMMA 的智能体协作任务上难以超越**随机基线**。这个信号表明，多模态多智能体能力尚未得到充分训练和评估 —— LLM 能 reasonably 处理单模态协作；但多模态协调会崩溃。

适用场景：你的系统涉及多模态或非对称信息协调时。COMMA 的零结果是一个警告：在宣称能力之前先测量。

### MedAgentBoard — 领域压力测试

arXiv:2505.12371。四类医疗任务：诊断、治疗规划、报告生成、患者沟通。比较多智能体 vs 单 LLM vs 传统基于规则的系统。

结论：在大多数类别中，多智能体并**不**优于单 LLM。多智能体的优势是窄小的 —— 当子任务清晰可分时（诊断 + 治疗），任务分解有帮助；但当协调开销超过专业化收益时（报告生成），多智能体反而有害。

适用场景：你的领域有明确的单 LLM 基线时。如果 MedAgentBoard 的经验可推广，许多提议的多智能体系统是过度设计的。

### AgentArch — 企业架构

arXiv:2509.10769。企业环境中工具使用、记忆和编排分层叠加。基准测试隔离各层的贡献：添加工具帮助多少？添加记忆帮助多少？添加多智能体编排帮助多少？

适用场景：你正在设计企业智能体栈并需要为每一层论证价值时。AgentArch 帮助你避免购买无法衡量价值的功能。

### SWE-bench Pro — 现实检验

arXiv:2509.16941。41 个仓库中 1865 个问题，覆盖商业应用、B2B 服务和开发者工具。设计为**不受污染**，使用较晚的训练截止日期。前沿模型在 Pro 上得分约 23%，而在 Verified 上得分 70%+。这个差距就是污染信号。

2026年4月得分：
- Claude Opus 4.7 在 Pro 上：**64.3%**（使用显式智能体团队协作报告；Anthropic 官方源尚未发布 —— 请视为初步结果）。
- Verdent（智能体脚手架）在 Verified 上：**76.1% pass@1**（[技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）。
- 无智能体脚手架的前沿模型在 Pro 上：约 23-35%（[SWE-bench Pro 论文](https://arxiv.org/abs/2509.16941)）。

关键结论："我们超过了 SWE-bench Verified"已不再是能力的证据。Pro 是当前门槛测试。智能体团队脚手架在 Pro 上产生可衡量的提升（约 30-40 分差距），这是 2026 年多智能体协调最有力的实证论据之一。

### AAAI 2026 WMAC

AAAI 2026 Bridge Program — 多智能体协调研讨会（https://multiagents.org/2026/）。2026 年多智能体 AI 研究的社区核心焦点。收录论文和研讨会论文集是评估新方法的标准场所；在生产决策中，优先参考 WMAC 收录论文的声明，而非 arXiv 预印本。

### 以怀疑态度解读基准声明 —— 2026 检查清单

当有人宣称多智能体结果时：

1. **哪个基准、哪个划分？** SWE-bench Verified vs Pro 差别很大。报在错误划分上的数字毫无价值。
2. **污染检查。** 该基准是否在模型训练截止日期之后发布？如果不是，请谨慎对待。
3. **基线对比。** 是与单 LLM 基线、随机基线、还是先前多智能体工作对比？不能是"与未调优的同系统版本对比"。
4. **统计显著性。** N 次试验、p 值、置信区间。前沿模型方差高；单次运行会误导。
5. **任务多样性。** 一个任务还是多个？泛化能力对生产环境至关重要。
6. **成本披露。** 每个任务的 token 数、墙钟时间。20 倍成本换来的 90% 解决方案是商业决策，不是能力声明。

### 当前基准未能良好衡量的方面

- **长周期协调。** 数天的墙钟交互。所有现有基准运行时间都很短。
- **对抗韧性。** 当一个智能体是恶意或受损时会发生什么？
- **部署下的漂移。** 基准是静态的；生产环境的分布会漂移。
- **成本归一化性能。** 多数基准报告原始准确率，而非每美元准确率。

为你真正关心的维度构建内部基准通常是正确做法。

## 构建它

`code/main.py` 是一个非交互式演示：

- 在玩具任务上模拟 3 个多智能体系统。
- 计算每个系统的 MARBLE 风格里程碑指标。
- 通过从"训练"集中撤出任务来执行污染检查。
- 明确与随机基线对比。
- 打印基准声明评分卡。

运行：

```bash
python3 code/main.py
```

预期输出：包含原始准确率、里程碑达成率、任务成本、与随机基线的差距的评分卡，以及污染检查说明。

## 使用它

`outputs/skill-benchmark-reader.md` 读取任意多智能体基准声明并应用检查清单。输出：评分和注意事项。

## 交付

生产环境评估规范：

- **构建反映实际生产分布的内部基准。** 公开基准提供参考，但不能替代。
- **在每个对比中包含随机基线。** 如果你在协调任务上无法大幅超越随机，该任务可能定义不当。
- **报告准确率的同时报告成本。** token 成本和墙钟时间。运维团队两者都需要。
- **每季度重建基准。** 生产分布会漂移；过时的基准会误导。
- **避免在公开基准上过拟合。** 如果你的团队专门优化 SWE-bench Pro 分数，你在生产环境中会倒退。

## 练习

1. 运行 `code/main.py`。确定三个模拟系统中哪个具有最佳的任务成本比。它是否与最高原始准确率的系统一致？
2. 阅读 MultiAgentBench（arXiv:2503.01935）。针对你自己的任务领域，决定 MARBLE 会推荐哪种拓扑。从论文的结论中给出理由。
3. 阅读 SWE-bench Pro 论文。它具体如何抵抗污染？同样的技术能否应用于你关心的其他基准？
4. 阅读 COMMA 关于多模态协调的发现。设计一个简单的多模态协调任务，你可以将其添加到内部基准中。什么样的结果算是有用的信号？
5. 将基准声明检查清单应用于最近一篇多智能体论文的标题结果。你会给这个声明打什么分数？
