# LLM 路由层 —— LiteLLM、OpenRouter、Portkey

> 供应商锁定成本高昂。不同的工具调用工作负载适合不同的模型。路由网关提供统一的 API 表面、重试、故障转移、成本跟踪和护栏。2026 年有三种主要范式：LiteLLM（开源自托管）、OpenRouter（托管 SaaS）、Portkey（生产级，2026 年 3 月开源）。本课命名决策标准，并演示标准的stdlib路由网关。

**类型：** 学习
**语言：** Python（stdlib，路由 + 故障转移 + 成本跟踪）
**先修知识：** 第13阶段 · 02（函数调用）、第13阶段 · 17（网关）
**时间：** 约45分钟

## 学习目标

- 区分自托管、托管和生产级路由方案。
- 实现一个在供应商失败时按定义优先级顺序重试的回退链。
- 跨供应商跟踪每个请求的成本和令牌用量。
- 根据生产约束在 LiteLLM、OpenRouter 和 Portkey 之间做出选择。

## 问题场景

需要供应商路由的场景：

1. **成本。** Claude Sonnet 的费用是 Haiku 的 3 倍。对于分诊任务，Haiku 足够；对于综合任务，Sonnet 值得。按请求路由。

2. **故障转移。** OpenAI 遇到故障小时。每个请求都失败。你想要自动回退到 Anthropic，无需重新部署。

3. **延迟。** 实时聊天界面需要快速的首次令牌时间。批量摘要器则不需要。按延迟 SLA 路由。

4. **合规。** EU 用户必须留在 EU 区域。按区域路由。

5. **实验。** 在同一工作负载上对两个模型进行 A/B 测试。按测试桶路由。

为每个集成单独编码所有这些工作是重复性的。路由网关提供一个 OpenAI 兼容的 API 并处理其余部分。

## 概念

### OpenAI 兼容代理形状

每个人都使用 OpenAI 格式。路由网关暴露 `/v1/chat/completions`，接受 OpenAI schema，并在内部代理到 Anthropic / Gemini / Cohere / Ollama / 任意后端。客户端不关心这些细节。

### 模型别名

无需固定快照 ID，你的代码说 `our_smart_model`。网关将别名映射到真实模型。当供应商推出新一代时，你在服务端更改别名；你的代码无需触碰。

### 回退链

```
主用: openai/gpt-4o
5xx 时: anthropic/claude-3-5-sonnet
5xx 时: google/gemini-1.5-pro
5xx 时: 拒绝
```

网关在配置中定义此规则。重试次数计入预算，因此回退级联不会使成本爆炸。

### 语义缓存

相同或近乎相同的提示命中缓存而非供应商。重复代理循环的节省可达 30% 至 60%。键基于嵌入；近乎相同的提示共享缓存槽。

### 护栏

网关级：

- **PII 脱敏。** 发送提示前使用正则或 ML 进行预处理。
- **策略违规。** 拒绝包含禁止内容的提示。
- **输出过滤器。** 清除完成结果中的泄漏。

Portkey 和 Kong 都提供有偏好的护栏。LiteLLM 将其设为可选。

### 每密钥速率限制

一个 API 密钥 = 一个团队。每密钥预算防止一个团队消耗共享配额。大多数网关支持此功能。

### 自托管 vs 托管权衡

| 因素 | LiteLLM（自托管） | OpenRouter（托管） | Portkey（生产级） |
|--------|----------------------|----------------------|----------------------|
| 代码 | 开源，Python | 托管 SaaS | 开源（2026年3月）+ 托管 |
| 设置 | 部署代理 | 注册 | 两者均可 |
| 供应商 | 100+ | 300+ | 100+ |
| 计费 | 自有密钥 | OpenRouter 积分 | 自有密钥 |
| 可观测性 | OpenTelemetry | 仪表板 | 完整 OTel + PII 脱敏 |
| 最佳适用 | 拥有 SRE 团队且需要数据主权的团队 | 快速原型 | 需要开箱即用护栏和合规的生产环境 |

当你拥有 SRE 团队并希望数据主权时，LiteLLM 胜出。当你想要单一订阅且无需基础设施时，OpenRouter 胜出。当你需要开箱即用的护栏和合规时，Portkey 胜出。

### 成本跟踪

每个请求携带 `provider`、`model`、`input_tokens`、`output_tokens`。乘以每模型每令牌价格（由网关维护的定价表获取）。支持按用户 / 按团队 / 按项目聚合。

### MCP 加路由

网关可以路由 LLM 调用 AND MCP 采样请求。当采样请求的 modelPreferences 偏好特定模型时，网关将其翻译到正确的后端。这是第13阶段 · 17（MCP 网关）和本课的路由网关有时会合并为同一服务的地方。

### 路由策略

- **静态优先级。** 列表中的第一个；错误时回退。
- **负载均衡。** 轮询或加权。
- **成本感知。** 选择满足延迟 / 质量的最便宜模型。
- **延迟感知。** 选择过去 N 分钟内最快的模型。
- **任务感知。** 提示分类器将编码路由到一个模型，摘要路由到另一个。

## 使用方式

`code/main.py` 在约 150 行中实现了路由网关：接受 OpenAI 形状的请求，翻译为每供应商存根，运行优先级回退链，跟踪每请求成本，并在输入上应用 PII 脱敏。用三个场景运行它：正常请求、主用供应商中断触发回退、PII 泄漏被脱敏捕获。

重点查看：

- `ROUTES` 字典：别名 -> 优先级排序的供应商列表。
- 回退循环在 5xx 时重试。
- 成本跟踪器将令牌用量乘以每模型费率。
- PII 脱敏器在转发前清除 SSN 格式的pattern。

## 练习

1. 运行 `code/main.py`。触发中断场景；确认回退落在第二个供应商且成本正确归因。

2. 添加语义缓存：提示的 SHA256 作为查找键；缓存命中立即返回。在重复调用中测量成本节省。

3. 添加提示分类器，将"code ..."提示路由到偏好智能的别名，将"summarize ..."提示路由到偏好速度的别名。

4. 设计每团队预算：每个团队有月度支出上限；网关在达到上限后拒绝请求。选择执行粒度（按请求或窗口化）。

5. 并排阅读 LiteLLM、OpenRouter 和 Portkey 文档。命名每个厂商独有的一个功能。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| 路由网关 | "LLM 代理" | 位于多个供应商前的统一 API 表面层 |
| OpenAI 兼容 | "遵循 OpenAI schema" | 接受 `/v1/chat/completions` 形状，翻译到任意后端 |
| 模型别名 | "our_smart_model" | 代码中的名称，网关映射到具体模型 |
| 回退链 | "重试列表" | 失败时尝试的有序供应商列表 |
| 语义缓存 | "提示嵌入缓存" | 键是提示的嵌入；近似重复项共享缓存命中 |
| 护栏 | "输入/输出过滤器" | 脱敏 PII，拒绝策略违规 |
| 每密钥速率限制 | "团队预算" | 限定到 API 密钥的配额 |
| 成本跟踪 | "每请求花费" | 聚合令牌用量 x 每模型价格 |
| LiteLLM | "开源代理" | 可自托管的开源路由网关 |
| OpenRouter | "托管 SaaS" | 基于积分计费的托管网关 |
| Portkey | "生产选项" | 开源 + 托管，内置护栏 |
