# 工具接口 — 为什么智能体需要结构化 I/O

> 语言模型产生 token。程序执行动作。两者之间的差距就是工具接口：一份契约，让模型可以请求动作，让宿主执行动作。每个 2026 年的栈——OpenAI、Anthropic 和 Gemini 上的函数调用；MCP 的 `tools/call`；A2A 的 task 部分——都是同一种四步循环的不同编码。本课命名了该循环，并展示了运行它所需的最小机械结构。

**类型：** 学习
**语言：** Python（标准库，无需 LLM）
**前置条件：** 第 11 阶段（LLM 补全 API）
**时间：** 约 45 分钟

## 学习目标

- 解释为什么只能生成文本的 LLM 无法自行对真实世界采取行动。
- 绘制四步工具调用循环（描述 → 决策 → 执行 → 观察），并指明每一步由谁负责。
- 将工具描述写成三部分：名称、JSON Schema 输入和确定性执行器函数。
- 区分纯工具和副作用工具，并说明这种区分对安全性的意义。

## 问题所在

LLM 输出的是下一个 token 的概率分布。这就是完整的输出表面。如果你问一个聊天模型"现在 Bengaluru 的天气怎么样"，它可以写出一句看似合理的句子，但无法拨入天气 API。这句话可能是巧合正确，也可能是三天前的过时数据。

填补这一差距正是工具接口的目的。宿主程序——你的智能体运行时、Claude Desktop、ChatGPT、Cursor 或自定义脚本——向模型声明一个可调用的工具列表。当模型判断需要执行某个动作时，它会输出一个结构化的载荷，指定工具名称及其参数。宿主解析该载荷，真实运行工具，并将结果反馈回去。循环持续进行，直到模型判断不再需要更多调用。

这份契约的第一版于 2023 年 6 月作为 OpenAI 的"functions"参数推出。Anthropic 随后在 Claude 2.1 中添加了 `tool_use` 块。Gemini 在几个月后添加了 `functionDeclarations`。每家供应商现在都暴露出相同的结构：输入是 JSON Schema 类型的工具列表，输出是 JSON 载荷的工具调用。模型上下文协议（2024 年 11 月）将该契约泛化，使一个工具注册表服务于所有模型。A2A（2026 年 4 月，v1.0）在同一条原语之上增加了智能体间委托功能。

四步循环是这一切背后的不变量。第 13 阶段的所有其他内容都是对该循环的展开。

## 概念解析

### 第一步：描述

宿主用三个字段声明每个工具。

- **名称。** 一个稳定的、机器可读的标识符。比如 `get_weather`，而不是"weather thing"。
- **描述。** 一段自然语言简述。"在用户询问特定城市的当前天气状况时使用。不要用于历史数据。"
- **输入 schema。** 一个 JSON Schema 对象（draft 2020-12），描述工具的参数。

模型接收该列表。现代供应商将这些声明通过供应商特定的模板序列化为系统提示，因此作为调用者你只需处理结构化形式。

### 第二步：决策

给定用户的消息和可用的工具，模型选择三种行为之一。

1. **直接回答。** 以文本形式回答，无需工具调用。
2. **调用一个或多个工具。** 输出结构化的调用对象。在 `parallel_tool_calls: true` 条件下（OpenAI 和 Gemini 默认为启用，Anthropic 需要显式 opt-in），模型可以在一个回合中发出多个调用。
3. **拒绝。** 严格模式的结构化输出可以生成一个类型化的 `refusal` 块，而非调用。

工具调用载荷有三个稳定字段：调用 `id`、工具 `name` 和 JSON `arguments` 对象。id 的存在是为了让宿主能够将后来的结果与特定的调用相关联，这在并行调用返回顺序不一致时很重要。

### 第三步：执行

宿主接收调用，根据声明的 schema 验证参数，然后运行执行器。无效参数意味着模型 hallucinated 了一个字段或使用了错误的类型——这在较弱的模型上是非常常见的失败模式。生产级宿主在遇到无效参数时会采取三种做法之一：快速失败并将错误反馈给模型、用约束解析器修复 JSON、或在提示中包含验证错误后重试模型。

执行器本身是普通代码。Python、TypeScript、shell 命令、数据库查询都可以。它产生一个结果，通常是一个字符串，但也可以是任何 JSON 值或结构化内容块（text、image 或 MCP 中的 resource reference）。结果必须是可序列化的。

### 第四步：观察

宿主将工具结果追加到对话中（作为带有匹配 `id` 的 `tool` 角色消息），然后重新调用模型。模型现在在上下文中有了工具输出，可以生成最终答案或请求更多调用。循环持续进行，直到模型停止发出调用或宿主达到迭代次数的安全限制。

### 信任分割

工具分为两种对安全性有意义的类型。

- **纯工具。** 只读、确定性、无副作用。`get_weather`、`search_docs`、`get_current_time`。可以安全地 speculative 调用。
- **结果性工具。** 改变状态、花费金钱、接触用户数据。`send_email`、`delete_file`、`execute_trade`。必须设置 gate。

Meta 2026 年的智能体安全"二规则"指出，单个回合最多可以组合以下三项中的两项：不可信输入、敏感数据、结果性动作。工具接口是你执行该规则的地方——通过拒绝调用、要求用户确认或升级权限范围。详见第 13 阶段 · 15 的安全章节和第 14 阶段 · 09 的智能体级权限策略。

### 循环在哪里运行

| 上下文 | 谁负责描述 | 谁负责决策 | 谁负责执行 |
|---------|---------------|-------------|--------------|
| 单回合函数调用（OpenAI/Anthropic/Gemini） | 应用开发者 | LLM | 应用开发者 |
| MCP | MCP server | 通过 MCP client 的 LLM | MCP server |
| A2A | Agent Card 发布者 | 调用方智能体 | 被调用方智能体 |
| Web 浏览器（函数调用智能体） | 浏览器扩展 / WebMCP | LLM | 浏览器运行时 |

无论在哪里，都是相同的四个步骤。列名不同；结构不变。

### 为什么不直接提示模型输出 JSON？

"提示模型以 JSON 形式回复"是函数调用之前的模式。它在前沿模型上失败率约为 5% 到 15%，在较小的模型上则更高。失败模式包括缺少花括号、尾随逗号、幻觉字段和错误类型。然后你需要一个 JSON 修复通道、重试或约束解码。

原生函数调用在三个方面更好。首先，供应商端到端训练模型处理精确的调用形状，因此在严格模式下有效 JSON 率升至 98% 到 99%。其次，调用载荷位于自己的协议槽中，不在自由文本内——因此工具调用永远不会泄漏到用户可见的回复中。第三，供应商通过约束解码强制执行 schema 合规性（OpenAI 的 strict mode、Anthropic 的 `tool_use`、Gemini 的 `responseSchema`）。输出得到保证可以验证。

### 熔断器

循环在模型停止发出调用或宿主达到最大回合数时终止。生产级宿主将其设置为 5 到 20 个回合之间。超过这个数量，你几乎肯定陷入了模型无法退出的循环。Claude Code 默认为 20；OpenAI Assistants 为 10；Cursor 的智能体模式为 25。

另一种选择——无界循环——每六个月就会出现一次"智能体在一夜之间花费了 400 美元 API 调用费"的事后总结文章。不要在没有边界的的情况下发布。

第 14 阶段 · 12 详细讲解错误恢复和自愈；第 17 阶段讲解生产速率限制。

## 动手实践

`code/main.py` 在不使用 LLM 的情况下运行四步循环。一个假的"决策者"函数通过对用户消息进行模式匹配来模拟模型；执行器、schema 验证器和观察步骤的 harness 都是真实的。运行它以查看完整的请求/响应编排及可打印的中间状态，然后在后续课程中将假决策者替换为任何真实的供应商。

值得关注的内容：

- 工具注册表为每个工具保存三个字段：名称、描述、schema 和执行器引用。
- 验证器是一个最小化的 JSON Schema 子集（类型、required、enum、min/max），仅用标准库编写。第 13 阶段 · 04 提供了一个更完整的版本。
- 循环将迭代次数限制为五次。生产级智能体需要这种类型的熔断器。

## 交付成果

本课生成 `outputs/skill-tool-interface-reviewer.md`。给定一个草稿工具定义（名称 + 描述 + schema + 执行器大纲），该 skill 会对其循环适配性进行审核：名称是否机器稳定、描述是否为完整的使用简述、schema 是否正确使用了 JSON Schema 2020-12、以及纯与结果性的分类是否明确。

## 练习

1. 在 `code/main.py` 中添加第四个工具 `get_stock_price(ticker)`。将其描述写为"在用户询问按股票代码的当前股价时使用。不要用于历史价格或市场摘要。"运行 harness 并确认假决策者将提及股票代码的查询路由到新工具。

2. 破坏 schema 验证器。传入一个 `arguments` 对象缺少必填字段的调用，并确认宿主在执行前拒绝了它。然后传入一个带有额外未知字段的调用。判断：宿主应该拒绝还是忽略？用安全论证来为你的选择辩护。

3. 将 harness 中的每个工具分类为纯工具或结果性工具。在需要标记的注册表条目中添加 `consequential: true` 标志，并更改循环，使其在选择结果性工具时打印"would confirm with user"行。这是每个生产级宿主都需要的那种确认 gate 的形状。

4. 在纸上绘制四步循环，并填入你最喜欢的客户端（Claude Desktop、Cursor、ChatGPT 或自定义栈）的供应商列表格。与第 13 阶段 · 06 中的 MCP 特定变体交叉参考。

5. 通读 OpenAI 的函数调用指南。找出请求中存在但本文呈现的四步循环中没有的字段。解释它增加了什么，以及为什么它是便利性的而非必要的。

## 关键术语

| 术语 | 人们怎么说 | 实际上是什么意思 |
|------|------------------------|-----------------------------------------------------------|
| 工具 | "模型可以调用的东西" | 名称 + JSON Schema 类型输入 + 执行器函数的三元组 |
| 函数调用 | "原生工具使用" | 供应商级 API 支持，用于输出结构化工具调用而非散文 |
| 工具调用 | "模型的行动请求" | 模型发出的包含 `id`、`name`、`arguments` 的 JSON 载荷 |
| 工具结果 | "工具返回的内容" | 执行器的输出，包装在带有匹配 id 的 `tool` 角色消息中 |
| 并行工具调用 | "一次性多个调用" | 模型单次输出中的多个调用对象，相互独立且可通过 id 排序 |
| 严格模式 | "保证 JSON" | 约束解码，强制模型输出符合声明的 schema |
| 纯工具 | "只读工具" | 无副作用；可安全重复运行 |
| 结果性工具 | "动作工具" | 改变外部状态；需要 gate、审计或用户确认 |
| 四步循环 | "工具调用周期" | 描述 → 决策 → 执行 → 观察 |
| 宿主 | "智能体运行时" | 持有工具注册表、调用模型、运行动执行器的程序 |
