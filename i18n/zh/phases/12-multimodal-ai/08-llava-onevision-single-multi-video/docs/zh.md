# LLaVA-OneVision：单图、多图、视频统一模型

> 在 LLaVA-OneVision（Li 等人，2024年8月）之前，开源 VLM 世界存在各自的分支谱系：LLaVA-1.5 专注单图，Mantis 和 VILA 等多图模型专攻多图，Video-LLaVA 和 Video-LLaMA 等视频模型处理视频。每个模型都能赢下对应基准，却在其他场景上失败。LLaVA-OneVision 提出：一个统一的课程训练可以让单个模型同时统治三种场景，且涌现的任务迁移效应（单图技能迁移到视频、多图推理迁移到单图）优于各专精模型的总和。配方看似简单：跨场景保持固定的视觉 token 预算，加上明确的课程顺序——从单图到 OneVision（多图）再到视频。本课时将解析预算分配、课程设计和涌现行为。

**类型：** 构建
**语言：** Python（标准库，token 预算求解器 + 课程规划器）
**前置要求：** 第 12 阶段 · 05（LLaVA）、第 12 阶段 · 06（任意分辨率）
**预计时间：** 约 180 分钟

## 学习目标

- 设计一个在单图、多图和视频输入中保持恒定的视觉 token 预算。
- 安排能将技能从单图迁移到视频且不灾难性遗忘的训练课程顺序。
- 解释为何得当的课程设计能让单模型在同参数量下超越专家模型。
- 列举 LLaVA-OneVision 报告的三种涌现能力：多相机推理、集合标记提示、iPhone 截图智能体。

## 问题背景

图像、多图和视频各自对模型施加不同的压力。

单图场景需要高分辨率 tokens（AnyRes，约 2880 个视觉 token）来捕捉 OCR 文本和细粒度细节。每个样本预算：一张图，2880 tokens。

多图场景需要多张中等分辨率图像（每图约 576 tokens），使跨图推理能容纳在上下文窗口内。每个样本预算：4-8 张图，每张 576，总计 2300-4600 tokens。

视频场景需要多帧低分辨率图像（池化后每帧约 196 tokens）以捕捉时间动态。每个样本预算：8-32 帧，每帧 196，总计 1600-6200 tokens。

若训练独立模型，只需选择一个预算。若要训练单一模型，则需要让预算跨场景合理缩放，同时不撑爆上下文窗口。

在 OneVision 之前，默认答案是"训练一个场景，忽略其他"。Video-LLaVA 通过额外训练阶段将视频适配到图像模型。LLaVA-NeXT 通过分块添加了多图支持。没有哪个方案能干净地同时处理三者。

## 概念解析

### OneVision token 预算

LLaVA-OneVision 选择一个统一的视觉 token 预算，每个样本约 3000-4000 tokens，按场景分配：

- 单图：AnyRes-9（3×3 分块 + 缩略图），每个分块 384，729 个 patches，激进的双线性池化 2×2 → 每块 182。总计：9 × 182 + 182 = 1820 tokens。或 AnyRes-4，每块 729 → 2916 + 729。
- 多图：每张图中等分辨率（384，不分块），729 tokens，无池化。6 张图预算 → 4374 tokens。
- 视频：32 帧 384 分辨率，激进 3×3 双线性池化 → 每帧 81 tokens。总计：32 × 81 = 2592 tokens。

分配方式保持总 token 数大致恒定。LLM 永远不会遇到撑爆上下文的批次。编码器按场景生成不同几何结构，但 LLM 消费的预算相同。

### 三阶段课程

LLaVA-OneVision 分三个阶段训练：

1. 单图 SFT（阶段 SI）。所有数据为单图加文本。在高精度 AnyRes 输入上训练。教授感知、OCR 和细粒度理解。使用 LLaVA-NeXT 数据加上 OneVision 专属单图数据。
2. OneVision SFT（阶段 OV）。混合单图 + 多图 + 视频（均匀采样帧）。在统一 token 预算上训练。教模型处理异构批次形状。不重置权重——从阶段 SI 继续。
3. 任务迁移（阶段 TT）。继续以目标任务混合训练，通常根据产品需求加重多图或视频比例。可选微调用于部署。

关键：课程顺序至关重要。训练顺序若为视频优先或多图优先，即使数据量相同，图像性能也劣于单图优先。论文对此做了明确消融实验。

### 为何课程有效

单图训练构建感知基础。patch token 携带细粒度视觉特征；LLM 学习将其与文本整合。多图和视频引入结构性挑战（哪张图是哪张、谁先发生），这些在没有强感知基础的情况下难以学习。

如果同时从零训练所有场景，模型会在感知上过拟合不足（每个批次单图数据有限）而在结构上过拟合过度（大量多图/视频数据）。结果是：一个遵循跨图推理模式但视觉理解浅薄的模型。

课程顺序让你从阶段 SI 获得感知强度，再从阶段 OV 获得组合/时序推理能力，且两者不丢失。

### 涌现跨场景技能

LLaVA-OneVision 论文报告了三种涌现能力：

1. **多相机推理**。训练时使用单独的多图和视频数据；推理时要求其对多相机驾驶场景进行推理。模型正确整合了各个视角，尽管训练时从未见过这种精确格式。
2. **集合标记提示**。用户用编号标记标注图像中的物体；模型推理"标记3相对于标记7在做什么"。既未训练标记也未训练标注；从空间定位 + 多图参考的组合中学到。
3. **iPhone 截图智能体**。用户提供 iPhone 屏幕截图并要求规划下一步点击。训练数据包括 UI 截图、用户工作流视频和多图前后对比对。泛化到智能体应用场景。

这些并非训练任务；它们从课程的组合结构中涌现。

### 视觉 token 池化

token 预算需要池化。OneVision 对 2D patch 网格使用双线性插值：24×24 = 576 patches 变为 12×12 = 144（2倍因子）或 8×8 = 64（3倍因子）。池化在 patch 网格空间完成，而非 token 空间，以保留局部性。

每个场景的池化因子选择本身是一个超参数。更少池化 = 更多 tokens = 更丰富表示。更多池化 = 更少 tokens = 可容纳更多帧/图像。

### LLaVA-OneVision-1.5

2025 年后续版本（LLaVA-OneVision-1.5，arXiv 2509.23661）在训练数据、模型权重和代码上完全开源。在某些基准上与闭源模型持平，并让配方民主化。采用相同课程，更多数据，更强的基础 LLM。无架构变更。

### 与 Qwen2.5-VL 对比

Qwen2.5-VL（第 12.09 课）做出不同选择。它使用 M-RoPE 和动态 FPS 而非固定池化。其预算随输入缩放——1 分钟视频比 5 秒视频使用更多 tokens。LLaVA-OneVision 固定预算并缩放池化。两者均可行；前者以可配置性换取可预测性。

## 使用示例

`code/main.py` 是 OneVision 风格 VLM 的课程和预算规划器。给定每个样本的 token 预算和目标场景混合比例（如 40% 单图、30% 多图、30% 视频），它：

- 为每个场景分配分辨率、池化因子和帧数。
- 验证所有场景是否在共享预算内。
- 报告预期 token 数量、LLM FLOPs，以及哪些场景 token 不足。
- 打印分阶段训练计划。

可用于规划 OneVision 微调，或验证 VLM 部署的每次请求成本。

## 交付物

本课产出 `outputs/skill-onevision-budget-planner.md`。给定目标任务分布和每个样本预算，输出 AnyRes 因子、每帧池化、视频帧数和课程阶段权重。在训练或微调统一场景 VLM 时均应使用此工具。

## 练习

1. 你的产品支持 80% 单图、10% 多图（2-4 张图）、10% 视频（8-16 帧）。设计 token 预算。将节省的重度多图预算分配到何处？

2. 阅读 LLaVA-OneVision 第 4.3 节（涌现能力）。提出一个课程可能解锁但论文未报告的第 4 种涌现技能。

3. 交换课程顺序——先训练多图，再单图，再视频。预测哪些基准会退化，以及原因。

4. 论文报告视频基准仅用每样本 8 帧训练。这能否泛化到推理时的 30 秒视频？最先出问题的是 token 预算还是时序推理？

5. 双线性池化将 24×24 patches 缩减到 12×12，每个维度减少 4 倍。用 Python 标准库实现该池化，并验证每个 2×2 块的均值与双线性输出匹配。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| OneVision 场景 | "单图、多图或视频" | 统一 VLM 处理的三种输入形状之一；预算跨场景恒定 |
| Token 预算 | "每个样本多少 tokens" | LLM 在每个训练/推理样本中看到的总视觉 tokens，通常 3000-4000 |
| 课程 | "训练顺序" | 为涌现迁移而设计的阶段排序（单图 → 多图 → 视频） |
| 双线性池化 | "token 缩减" | 对 patch 网格（2D）应用双线性插值以减少 token 数同时保留局部性 |
| 涌现技能 | "未训练但仍有效" | 在推理时出现但未匹配训练数据的技能，源于课程组合 |
| AnyRes-k | "k 分块设置" | k 个固定分辨率子分块加一个缩略图，典型 k ∈ {4, 9} |
| 任务迁移 | "跨场景泛化" | 在单图上学习的技能通过共享骨干网络应用到视频（反之亦然） |
