# 多模态智能体与计算机使用（毕业设计）

> 2026年的前沿产品是一个多模态智能体，能够读取屏幕截图、点击按钮、导航网页界面、填写表单，并端到端完成工作流程。SeeClick 和 CogAgent（2024年）验证了 GUI 定位原语。Ferret-UI 扩展到了移动端。ChartAgent 引入了面向图表的视觉工具使用。VisualWebArena 和 AgentVista（2026年）是前沿追逐的基准——即便是 Gemini 3 Pro 和 Claude Opus 4.7 在 AgentVista 的难题上也只能达到约 30% 的得分。本毕业设计整合了第 12 阶段的所有线索：感知（高分辨率 VLM）、推理（带工具使用的 LLM）、定位（坐标输出）、长程记忆和评估。

**类型：** 毕业设计
**语言：** Python（标准库、动作模式定义 + 智能体循环骨架）
**前置知识：** 第 12 阶段 · 05（LLaVA）、第 12 阶段 · 09（Qwen-VL JSON）、第 14 阶段（智能体工程）
**时间：** 约 240 分钟

## 学习目标

- 设计多模态智能体循环：感知 → 推理 → 执行 → 观察 → 重复。
- 构建 GUI 定位输出模式（点击坐标、输入文本、滚动、拖拽），让 VLM 能将其输出为 JSON。
- 对比仅依赖截图的智能体与依赖辅助功能树智能体及混合智能体。
- 在小规模 VisualWebArena 切片上搭建多模态智能体基准评估。

## 问题描述

一个订票网站的工作流程："帮我找一张 4 月 15 日飞往东京的航班，靠过道座位，价格在 800 美元以内，完成预订。"

一个多模态智能体需要：

1. 截取浏览器屏幕截图。
2. 解析截图 + URL + 目标，制定计划。
3. 输出结构化动作：点击（在 x,y）、输入 "Tokyo"（在元素 E）、向下滚动、选择（单选按钮）。
4. 将动作应用到浏览器。
5. 观察新状态（下一张截图）。
6. 重复直到任务完成。

每一步都是一个多模态 VLM 调用。VLM 输出必须是可解析的 JSON。错误会在步骤间累积，因此恢复机制至关重要。

## 概念解析

### GUI 定位——原语

GUI 定位是：给定一张截图和一段自然语言指令，输出要点击的 (x, y) 坐标（或其他动作）。

SeeClick（arXiv:2401.10935）是首个大规模开源成果：在合成 + 真实 GUI 数据上微调 VLM，将坐标输出为纯文本 token。可行。

CogAgent（arXiv:2312.08914）增加了 1120x1120 高分辨率编码，适用于密集 UI。得分：约 84% 的网页导航准确率。

Ferret-UI（arXiv:2404.05719）专注于移动端 UI，与 iOS 辅助功能数据集成。

输出格式通常为 JSON：

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

`element_desc` 有助于恢复：如果坐标在截图间发生漂移，语义提示能让系统重新定位。

### 动作模式

典型的动作模式包含 6-10 种动作类型：

- `click`：(x, y)
- `type`：(text, x?, y?)
- `scroll`：(direction, amount)
- `drag`：(x0, y0, x1, y1)
- `select`：(option_index)
- `hover`：(x, y)
- `navigate`：(url)
- `wait`：(ms)
- `done`：(success, explanation)

智能体每步输出一个动作。浏览器封装执行后返回新状态。

### 仅截图 vs 辅助功能树

两种输入模式：

- 仅截图：完整图像，无结构信息。最通用；适用于任何应用。
- 辅助功能树：结构化 DOM / iOS 辅助功能信息。定位更可靠；仅在树可用时有效。
- 混合模式：两者兼用，以树作为原子动作的可靠定位器，以截图提供语义上下文。

生产环境中的智能体在可能时使用混合模式。浏览器自动化（Selenium + 辅助功能）始终有树；桌面应用有时有。

### 长程记忆

一个 20 步的工作流会产生 20 张截图。VLM 的上下文很快填满。三种压缩策略：

- 摘要链：每 5 步后，总结已发生的事项，丢弃旧截图。
- 跳过帧：保留第一张、最后一张和每隔 3 张的截图。
- 工具记录日志：执行动作，保留已做什么的文本日志；不重新查看旧截图。

Claude 的 computer-use API 使用日志模式。更简单、更可靠。

### 视觉工具使用

ChartAgent（arXiv:2510.04514）引入了面向图表理解的视觉工具使用：裁剪、缩放、OCR、调用外部检测。智能体可以输出 "裁剪到区域 (100, 200, 300, 400) 然后调用 OCR" 作为工具调用。工具返回文本；VLM 继续推理。

此模式可推广：标记集合提示、区域标注和外部检测工具都符合相同的 "输出工具调用、接收结构化响应" 模式。

### 2026 年基准测试

- ScreenSpot-Pro。在约 1k 网页截图上进行 GUI 定位。开源 SOTA Qwen2.5-VL-72B 约 85%。前沿模型约 90%。
- VisualWebArena。端到端网页任务（购物、论坛、分类广告）。开源 SOTA 约 20%。Gemini 3 Pro 约 27%。
- AgentVista（arXiv:2602.23166）。最难的 2026 年基准。跨 12 个领域的真实工作流程。前沿模型得分 27-40%；开源模型 10-20%。
- WebArena / WebShop。较旧的基准；已被前沿模型饱和。

### 为何仍然困难

智能体性能瓶颈：

1. 细粒度视觉定位。"点击小的 X" 在移动端分辨率下经常失败。
2. 长程规划。经过 10 个动作后，智能体偏离目标。
3. 错误恢复。当点击失败（点错按钮）时，检测 + 恢复很少在训练数据中。
4. 跨页面上下文。在标签页间跳转或处理长表单时会丢失状态。

研究方向：记忆架构、显式重规划、多模态验证（截图匹配动作是否成功）。

### 毕业设计构建任务

毕业设计任务：构建一个 computer-use 智能体，能够：

1. 读取订票网站模拟页面的 HTML + 截图。
2. 规划多步序列：搜索 → 选择 → 填写表单 → 提交。
3. 输出匹配动作模式的 JSON 动作。
4. 在固定的 10 任务切片上评估。

1. 用 `screenshot_region` 工具扩展动作模式（裁剪 + 缩放）。哪些任务会受益？

2. 阅读 AgentVista（arXiv:2602.23166）。描述最难的任务类别以及为何前沿模型仍然失败。

## 关键术语

| 术语 | 人们说的 | 实际含义 |
|------|---------|---------|
| GUI 定位 | "点击坐标" | 模型在截图上针对指令输出目标的 (x,y) |
| 动作模式 | "工具定义" | 有效动作的 JSON 描述（点击、输入、滚动、拖拽） |
| 辅助功能树 | "结构化 DOM" | 从浏览器/iOS API 获得的机器可读 UI 层次结构 |
| 混合智能体 | "截图 + 树" | 同时使用图像和结构信息；比单独使用任一更可靠 |
| 视觉工具使用 | "缩放/裁剪/检测" | 智能体在规划中途调用外部视觉工具（OCR、检测） |
| 摘要链 | "记忆压缩" | 定期文本摘要替换长截图历史 |
| VisualWebArena | "端到端网页基准" | 2024 年端到端网页任务的基准 |
| AgentVista | "2026 年难题基准" | 12 个领域的真实工作流程；即便是 Gemini 3 Pro 也只能得分约 30% |
