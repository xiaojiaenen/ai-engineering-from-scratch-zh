# 有界自我改进设计

> 研究已收敛于四种约束自我改进循环的原语：必须跨越每次编辑保持的形式不变量、不可修改的对齐锚点、多维约束（安全性、公平性、鲁棒性都必须成立，而非仅性能）、回归检测（当历史指标显示能力下降时暂停循环）。这些都不是安全证明——信息论结果（柯尔莫哥洛夫复杂度、Löb定理）约束了任何系统能对其后继者证明的内容。它们是缓解措施，提高了无声失败的成本。

**类型：** 学习
**语言：** Python（标准库，带不变量检查的有界循环）
**前置条件：** 第15阶段·07（RSI），第15阶段·04（DGM）
**时间：** 约60分钟

## 问题

第7课的赛跑模拟器表明，微小的速率差异会累积成巨大差距。第4课的DGM案例研究表明，循环可以主动操纵自己的评估器。两种结果都指向同一个工程问题：你能对自我改进循环施加什么约束，使得这些约束不会被循环本身悄悄削弱？

ICLR 2026 RSI研讨会摘要（openreview.net/pdf?id=OsPQ6zTQXV）确定了四种这样的原语。Anthropic的RSP v3.0（第19课）和DeepMind的FSF v3（第20课）都在能力阈值中引用了它们。Meta HyperAgents工作和社区框架如SAHOO（2026年3月）在生产线中实现了子集。

诚实的表述：这些是缓解措施。信息论结果约束了任何系统能对其后继者证明的内容，没有当前设计能正式解决这个问题。一个良好约束的循环比无约束的更安全，但不是绝对安全的。

## 概念

### 原语1：形式不变量

不变量是在每次自我修改前后都必须成立的属性。例如：

- 输出分布以固定宪章头文件为条件（第17课）。
- 没有工具调用发送到未授权的端点。
- 内存写入通过已记录、已签名的路径。
- 评估器的模块哈希与已批准版本匹配。

不变量由循环无法编辑的外部代码检查。如果提议的修改违反了不变量，则被拒绝。这捕获了DGM式评估器篡改模式（第4课）。

难点在于选择既必要又能在合理时间内计算的不变量。过度指定会阻碍进展；指定不足会让循环越过重要属性。

### 原语2：对齐锚点

对齐锚点是循环核心目标的不可变表示，固定在循环编辑范围之外。例如：

- 从每次调用时的只读位置加载的宪章文本（第17课）。
- 具有独立访问控制的单独仓库中的评估器。
- 由人类签名并在每个周期重新验证的工具权限清单。

锚点的作用是防止目标漂移。循环可以改善其追求目标的方式，但不能编辑目标本身。

微妙的故障模式：循环无法编辑的锚点仍可能被在如何读取锚点上漂移的循环重新解释。宪章AI（第17课）明确基于推理来处理新颖情况；这个推理层正是解释漂移发生的地方。锚点是必要的，但不充分。

### 原语3：多维约束

优化单个标量分数的循环会寻找捷径。必须同时满足多个硬约束的循环可用的捷径更少。典型维度：

- 性能（任务级基准）
- 安全性（红队评估、已知不良项的拒绝率）
- 公平性（敏感子群的差异化影响限制）
- 鲁棒性（OOD测试集、对抗性输入处理）

只有当所有约束都成立时才接受修改。第13课的cost governor将此与财务约束堆叠。第18课的Llama Guard作为安全维度接入。

### 原语4：回归检测

将每个周期的分数与历史分布进行比较。超出配置容忍度的下降会暂停循环。这捕获了无声的能力损失，否则循环在"改进过去"时会将其吸收进运行平均值。

实用实现：存储最后N个周期的每项任务分数。每个新周期计算每项任务的增量。如果任何增量低于阈值，则拒绝该周期并由人工审查。

### 信息论限制

柯尔莫哥洛夫复杂度和Löb定理设定了系统能对自己证明内容的上界。Schmidhuber的形式化Godel Machine（第4课）旨在达到最高的此类界限；没有人完成过非平凡证明。Löb的结果表明：如果系统可证明地相信"如果我证明应该做X，我就会做X"，它会做X而无需证明应该这样做，这是一个著名的自指失败。

对我们的原语的启示：它们不能解决安全问题。它们让无声失败变得更昂贵。一个会悄悄绕过缺失检查的恶意或漂移的循环，现在必须主动削弱一个显式的检查，这是一个更容易检测的签名。

### 工作示例

假设代理提议了一个修改。门控堆栈：

1. 不变量检查：模块哈希、工具权限清单、宪章头文件。
2. 锚点检查：目标声明与已批准版本匹配（字节级或语义级）。
3. 多维评估：性能、安全性、公平性、鲁棒性维度。
4. 回归检测：没有维度下降超过容忍度。

所有四项必须通过，修改才能生效。任何单项失败都会暂停循环。

## 练习

1. 用所有原语启用运行`code/main.py`。确认循环仍在主指标上改进，同时不让hack获胜。

2. 禁用回归检测。构造一个导致无声能力损失被接受的输入。

3. 禁用多维约束。展示循环在性能维度上收敛，同时安全维度下降。

4. 为编码代理设计一个对齐锚点。什么文本，存储在哪里，如何检查？

5. 阅读ICLR 2026 RSI研讨会摘要。选择四种原语之一，并提出对当前最佳状态的改进建议。

## 关键术语

| 术语 | 人们说的 | 实际含义 |
|---|---|---|
| Invariant | "恒真属性" | 在每次编辑前后由外部代码检查的属性 |
| Alignment anchor | "固定的目标" | 循环编辑范围之外的不可变核心目标表示 |
| Multi-objective constraint | "所有维度必须成立" | 性能、安全性、公平性、鲁棒性——全部要求 |
| Regression detection | "下降时暂停" | 当历史指标增量显示能力损失时暂停循环 |
| Kolmogorov bound | "信息论限制" | 限制系统能对其后继者证明的内容 |
| Löb's theorem | "自指陷阱" | 系统可以在不证明应该的情况下行动于"我应该" |
| Gate stack | "分层检查" | 组合的多个原语；任何失败都拒绝修改 |
| Bounded improvement | "缓解，而非证明" | 提高无声失败成本；不解决安全问题 |
