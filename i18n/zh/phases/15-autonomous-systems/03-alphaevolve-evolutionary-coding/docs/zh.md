# AlphaEvolve — 进化式编程智能体

> 将前沿编程模型与进化循环和机器可验证评估器配对。让循环运行足够长时间。它发现了一种使用 48 次标量乘法的 4x4 复矩阵乘法程序——56 年来对 Strassen 算法的首次改进。它还找到了一种 Google -wide Borg 调度启发式算法，在生产中回收了约 0.7% 的集群算力。架构本身是刻意的平淡。真正起作用的，是评估器的严谨性。

**类型：** 学习
**语言：** Python（标准库、进化循环玩具实现）
**前置知识：** Phase 15 · 01（长视野框架），Phase 15 · 02（自主推理）
**时间：** 约 60 分钟

## 问题所在

大型语言模型可以编写代码。进化算法可以在代码空间中搜索。两者分别尝试了数十年；都遇到了天花板。LLM 的天花板是**虚构**：模型写出看似合理的代码，但其实际行为与声称不符。进化算法的天花板是**搜索成本**：在语法层面的随机变异很少产生可编译的程序，更不用说更好的程序了。

AlphaEvolve（Novikov 等，DeepMind，arXiv:2506.13131，2025年6月）将两者结合。LLM 对程序数据库提出针对性修改；自动评估器对每个变体打分；高分变体成为未来世代的父本。LLM 负责编写看似合理代码的高成本步骤；评估器捕获那些虚构。循环运行数小时到数周。

报告的结果：48 次标量乘法的 4x4 复矩阵乘法（Strassen 1969 年的界为 49），Google 生产环境的 Borg 调度启发式算法，FlashAttention 内核 32.5% 加速，Gemini 训练吞吐量提升。

架构之所以有效，是因为评估器是机器可验证的。在评估器不存在的领域，它就不起作用。这种不对称性才是核心教训。

## 概念解析

### 进化循环

1. 从正确但次优的种子程序 `P_0` 开始。
2. 维护一个变体程序数据库，每个程序均由评估器打分。
3. 从数据库采样一个或多个父本（基于 MAP-elites 风格或岛屿模型）。
4. 提示 LLM（Gemini Flash 用于生成大量候选，Gemini Pro 用于处理困难案例）产生基于父本的修改变体。
5. 编译、运行、在保留测试集评估器上评估该变体。
6. 按其得分和特征向量插入数据库。
7. 重复。

两个细节至关重要。首先，LLM 的提示不仅仅包含父本程序——通常包括数据库中若干个顶级变体、评估器签名，以及简短的任务描述。模型的任务是提出可能提升分数的针对性修改。其次，数据库是结构化组织（MAP-elites 网格、岛屿模型），以确保循环探索多样性，而非仅仅追逐当前最优解。

### 评估器为何不可妥协

AlphaEvolve 的所有胜利均来自评估器快速、确定且难以作弊的领域：

- **矩阵乘法算法**：单元测试，将矩阵相乘并逐位检查等式。
- **Borg 调度启发式**：生产级模拟器，重放历史集群负载并测量浪费的算力。
- **FlashAttention 内核**：正确性测试加上真实硬件上的墙钟基准测试。
- **Gemini 训练吞吐量**：每一步的 GPU 秒数。

每种情况下，评估器捕获了否则将占据主导的 LLM 错误类型：虚构的正确性声明、在硬件上消失的性能主张、边界情况失败。移除评估器后，循环只会优化"漂亮的代码"。

### 奖励黑客是同一枚硬币的另一面

进化算法优化的是评估器所测量的任何东西。如果评估器不完美，循环会找到其缺陷。在未验证领域，循环将优化表面特征，而非预期行为。DeepMind 在论文中明确指出：AlphaEvolve 的成功仅转移到评估器严谨性匹配搜索雄心的领域。

2025-2026 年代码搜索循环中奖励黑客的具体示例：

- "完成时间"优化目标奖励提交空解决方案。
- 基准分数奖励在测试下正确性，导致记忆测试并过拟合。
- "代码质量"代理奖励删除注释并重写变量名，无任何语义变化。

AlphaEvolve 的应对：交付 LLM 从未见过的保留测试评估器，输入在评估时生成。即便如此，DeepMind 仍建议在任何拟议部署前进行严格审查。

### 为何 LLM + 搜索胜于单独使用任一

LLM 能产生可编译、语义合理的修改。随机变异 GA 作用于 2000 行 Python 文件几乎总会产生语法错误。LLM 还将搜索集中在合理邻域（修改一个函数，而非随机字节），大幅减少浪费的评估器调用。

评估器反过来捕获 LLM 的虚构。LLM 会自信地声称某函数"极限下是 O(n log n)"，而实际上是 O(n²)；墙钟基准测试使这个问题得到裁决。

### AlphaEvolve 在前线技术栈中的位置

| 系统 | 生成器 | 评估器 | 领域 | 示例胜利 |
|---|---|---|---|---|
| AlphaEvolve | Gemini | 正确性 + 基准测试 | 算法、内核、调度器 | 48 次乘法 4x4 矩阵乘法 |
| FunSearch（DeepMind，2023） | PaLM / Codey | 正确性 | 组合数学 | 帽集下界 |
| AI Scientist v2（Sakana，L5） | GPT/Claude | LLM 评审 + 实验 | ML 研究 | ICLR 研讨会论文 |
| Darwin Godel Machine（L4） | 智能体脚手架 | SWE-bench / Polyglot | 智能体代码 | 20% → 50% SWE-bench |

四者都是同一配方（生成器 + 评估器 + 循环）的变体。差异在于评估器评分的内容及其严谨程度。

## 实践操作

`code/main.py` 在玩具符号回归问题上实现了最小化的 AlphaEvolve 式循环。"LLM"是标准库代理，对计算目标函数的程序提出小范围语法变异。"评估器"测量在保留测试点上的均方误差。

观察：

- 最优分数如何随代数提升。
- MAP-elites 网格如何保持多样解存活，防止循环收敛于局部最小值。
- 移除保留测试（仅训练评估器）如何让循环严重过拟合。

## 练习

1. 运行 `code/main.py`。记录最优分数轨迹。禁用保留测试评估器（参数 `--no-holdout`）并重新运行。量化过拟合程度。

2. 阅读 AlphaEvolve 论文第 3 节关于 MAP-elites 网格的内容。为新问题（如编译器优化阶段）设计一个特征向量描述符，以保持搜索多样性。

3. 48 次乘法 4x4 结果在 56 年后改进了 Strassen 的 49 次乘法界。阅读论文附录 F，并用三句话解释为何此问题的评估器特别容易做到位，以及为何大多数领域不像它这样。

4. 提出一个 AlphaEvolve 会失败的领域。明确指出评估器在何处失效及原因。

5. 对于你熟悉的领域，写出你会使用的评估器签名。包括：(a) 正确性条件，(b) 性能指标，(c) 保留测试输入生成规则，(d) 至少一项反奖励黑客检查。

## 关键术语

| 术语 | 人们所说的 | 实际含义 |
|---|---|---|
| AlphaEvolve | "DeepMind 的进化编程智能体" | Gemini + 程序数据库 + 机器可验证评估器 |
| MAP-elites | "多样性保存归档" | 按特征向量键索引的网格；每个单元格持有具有该描述符的最佳变体 |
| 岛屿模型 | "并行进化子种群" | 定期迁移的独立种群；防止过早收敛 |
| 机器可验证评估器 | "确定性预言机" | LLM 无法伪造的单元测试、模拟器或基准测试——此循环的前提条件 |
| 奖励黑客 | "优化测量而非目标" | 循环找到最大化分数但不执行预期任务的方法 |
| 种子程序 | "起始点" | 循环进化的初始正确但次优程序 |
| 保留测试评估器 | "LLM 从未见过的评估数据" | 在评估时生成的输入，防止记忆 |
