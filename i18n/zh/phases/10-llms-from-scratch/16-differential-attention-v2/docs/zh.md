# 差分注意力（V2）

> Softmax 注意力会在所有非匹配 token 上分散一小部分概率。在 10 万个 token 的情况下，这种噪声会累积并淹没信号。差分 Transformer（Ye 等，ICLR 2025）通过以两个 softmax 之差来计算注意力，从而减去共享的噪声基底来解决这一问题。DIFF V2（微软，2026 年 1 月）是面向生产栈的重写版本：匹配基线 Transformer 的解码延迟，无需自定义算子，兼容 FlashAttention。本课程完整涵盖 V1 到 V2 的流程，并附带一个可在标准 Python 中运行的差分运算玩具实现。

**类型：** 构建
**语言：** Python（标准库）
**前置条件：** 阶段 7 · 02（自注意力）、阶段 7 · 15（注意力变体）、阶段 10 · 14（架构详解）
**预计时间：** 约 60 分钟

## 学习目标

- 精确陈述 Softmax 注意力为何存在噪声基底，以及该基底为何随上下文长度增长。
- 推导差分注意力公式，并解释为何减法能抵消共享噪声分量而保留信号。
- 梳理 V1 到 V2 的变更：哪些更快、哪些更简单、哪些更稳定，以及每项变更对生产级预训练为何必要。
- 从零用纯 Python 实现差分注意力，并在合成信号加噪声查询上实证验证其消噪特性。

## 问题所在

标准 Softmax 注意力有一个在规模扩展时会变成工程难题的数学特性。对于查询 `q`，注意力权重为 `softmax(qK^T / sqrt(d))`。Softmax 永远无法产生精确的零——每个非匹配 token 都会获得一定的正质量。这部分剩余质量就是噪声，它随上下文长度而放大。在 128k token 时，即使每个非匹配 token 只分到 0.001% 的概率，127,999 个 token 合计也会贡献约 12% 的总概率。模型被迫学会绕过一个随上下文增长的噪声基底。

从经验上看，这表现为注意力头的相互干扰：长上下文 RAG 中的幻觉引用、10 万 token 检索任务中的"迷失中间"现象，以及超过 32k 时在 haystack 针测试基准上的微妙精度下降。《差分 Transformer》论文（arXiv:2410.05258，ICLR 2025）中测量到的差距表明：与同规模基线相比，DIFF Transformer 达到了更低的困惑度、更高的长上下文精度，以及更少的幻觉。

DIFF V1 存在三个问题，使其难以进入前沿预训练流水线。它的 value cache 在每个解码步需要加载两次，它要求破坏 FlashAttention 兼容性的自定义 CUDA 算子，且其逐头 RMSNorm 在 70B 以上规模的长期训练中不稳定。DIFF V2（微软 unilm 博客，2026 年 1 月 20 日）解决了上述三个问题。本课程会依次讲解两个版本，构建差分算子，并在玩具查询上对消噪能力进行基准测试。

## 概念解析

### Softmax 的噪声基底

对于查询 `q` 与键 `K = [k_1, ..., k_N]`，注意力权重为：

```
w_i = exp(q · k_i / sqrt(d)) / sum_j exp(q · k_j / sqrt(d))
```

没有任何 `w_i` 会真正为零。如果 `k_i` 与 `q` 完全无关，得分 `q · k_i` 也不会是 0——它会在 0 附近波动，方差约为 `||q||^2 / d`。经过 Softmax 归一化后，每个无关 token 对加权求和仍贡献 `O(1/N)`。无关 token 的总贡献为 `O((N-1)/N) = O(1)`——这不是一个小量。

模型真正想要的是类似硬 top-k 的效果：对匹配 token 赋予高权重，其余位置权重接近零。Softmax 过于平滑，无法直接做到这一点。

### 差分思路

将每个头的 Q 和 K 投影各拆成两部分：Q = (Q_1, Q_2) 与 K = (K_1, K_2)。计算两张注意力图：

```
A_1 = softmax(Q_1 K_1^T / sqrt(d))
A_2 = softmax(Q_2 K_2^T / sqrt(d))
```

输出为：

```
DiffAttn = (A_1 - lambda * A_2) V
```

减法会抵消两张图所共享的噪声分布。如果两张图在 12.7 万个无关 token 上都大致呈均匀权重（这在随机初始化时确实如此），那么这些噪声就会相互抵消。信号——即在少数真正相关 token 上的峰值权重——只有在两张图以相同量级出现时才会被抵消，而在模型训练后这种情况不会出现。

`lambda` 是一个逐头可学习标量，参数化为 `lambda = exp(lambda_q1 · lambda_k1) - exp(lambda_q2 · lambda_k2) + lambda_init`。它可以取负值。`lambda_init` 默认设为一个较小的正数，如 0.8。

### 为什么这与有向消噪相匹配

可以把两张有噪声的麦克风同时录制同一段语音。两者都会拾取说话者声音以及相关背景噪声。将其中一张减去另一张，共享噪声就会消失。而语音之所以幸存，是因为两路信号在相位或振幅上存在足够差异以避免完全抵消。逐头 `lambda` 正是学会这一平衡。

### V1 与 V2 的差异

V1 将参数量与基线 Transformer 保持相等。为了在每个头获得两个查询，它将头维度减半。这牺牲了头的表达能力，并且更痛苦的是，每个头的 value cache 容量也减半了。解码时必须每步加载两次 value cache（每个 softmax 分支各一次）。结果是：尽管参数量与基线持平，解码速度却慢于基线。

V2 将查询头数量翻倍，同时保持 KV 头数量不变（从 up-projection 借用参数）。头维度与基线保持一致。在减法完成后，额外的维度会再次投影回与基线 Transformer 的 O_W 投影相匹配的大小。这三件事同时发生：

1. 解码速度与基线持平（KV cache 只需加载一次）。
2. FlashAttention 可无改动运行（无需自定义算子）。
3. 解码时的算术强度提升（每次从 HBM 加载的字节对应更多计算量）。

V2 还去掉了 V1 用于稳定减法过程的逐头 RMSNorm。在 70B 量级的预训练规模下，该 RMSNorm 会引发训练后期的不稳定。V2 以一套更简单的初始化方案取而代之，在不引入额外模块的前提下保持训练稳定。

### 何时选用

| 工作负载 | 收益 |
|----------|------|
| 长上下文 RAG（64k+） | 注意力图更干净，幻觉引用更少 |
| Haystack 针测试基准 | 超过 32k 时精度显著提升 |
| 多文档 QA | 跨文档干扰更少 |
| 8k 长度代码补全 | 收益边际，不值得做架构改动 |
| 短对话（< 4k） | 与基线几乎无法区分 |

收益随上下文长度增长。在 4k token 时，噪声基底足够小，标准注意力即可胜任。在 128k 时，它就在拖后腿了。

## 动手构建

`code/main.py` 以纯 Python 实现了差分注意力。一个带有已知信号加噪声结构的玩具查询，让你可以直接测量消噪比。

### 步骤 1：标准 Softmax 注意力

使用标准库矩阵运算：嵌套列表、手动矩阵乘法、以及通过减去最大值来保证数值稳定性的 softmax。

```python
def softmax(row):
    m = max(row)
    exps = [math.exp(x - m) for x in row]
    s = sum(exps)
    return [e / s for e in exps]
```

### 步骤 2：将 Q、K 拆成两半

V1 风格：将头维度减半。V2 风格：保持头维度不变并将头数量翻倍。玩具实现采用 V1 风格以利于教学清晰性——数学本质完全一致，只是簿记方式不同。

### 步骤 3：两个 Softmax 分支 + 相减

```python
A1 = [softmax([dot(q1, k) / scale for k in K1]) for q1 in Q1]
A2 = [softmax([dot(q2, k) / scale for k in K2]) for q2 in Q2]
diff_weights = [[a1 - lam * a2 for a1, a2 in zip(r1, r2)] for r1, r2 in zip(A1, A2)]
out = [[sum(w * v[j] for w, v in zip(row, V)) for j in range(d_v)] for row in diff_weights]
```

注意：输出权重可以为负。这没问题——value cache 仍然能处理带符号的贡献。后续的 V 投影会吸收符号。

### 步骤 4：消噪测量

构建一个长度为 1024 的合成序列。在已知位置放置信号 token，其余位置填满噪声。分别计算（a）标准 Softmax 注意力在信号位置的权重，以及（b）差分注意力在信号位置的权重。测量两者的信噪比。DIFF 注意力通常能产生高出 3 到 10 倍的信噪比，具体倍数取决于两个分支的训练分化程度。

### 步骤 5：V1 与 V2 的参数核算

给定配置（hidden=4096, heads=32, d_head=128），输出：

- 基线 Transformer：Q、K、V 各为 `hidden * hidden`，MLP 为 4 * hidden。
- DIFF V1：Q、K 各为 `hidden * hidden`，V 为 `hidden * hidden`（未变），头维度在内部减半。增加逐头 `lambda` 参数（O(heads * d_head)）。
- DIFF V2：Q 为 `2 * hidden * hidden`，K 为 `hidden * hidden`，V 为 `hidden * hidden`。额外的维度在 O_W 之前被投影回原大小。同样增加 `lambda` 参数。

玩具实现会测量 V2 带来的额外参数开销（每个注意力块大约多出 `hidden * hidden`），并将其打印出来。

## 使用方式

截至 2026 年 4 月，DIFF V2 尚未在所有生产推理服务器中上线，但 vLLM 和 SGLang 的集成已在推进中。与此同时，这一模式已出现在以下场景：

- 微软内部的长上下文生产模型。
- 若干开放模型训练中针对 256k+ 上下文的复现研究。
- 在不同层交替使用差分注意力与滑动窗口注意力的混合架构。

在 2026 年你应当采用它的时机：

- 从头训练一个目标有效上下文 64k+ 的新模型。从一开始就加入差分注意力；事后重新训练代价高昂。
- 微调一个长上下文模型，且"迷失中间"失效主导了你的评估表现。在 Q 投影上施加 LoRA 即可近似 DIFF 结构。

你不应采用的时机：

- 你正在部署一个预训练稠密模型，其长上下文性能已很稳定。针对已有权重做重新训练的代价很难得到回报。
- 你的上下文始终低于 16k。此时噪声基底可忽略不计。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| 差分注意力 | "两个 Softmax 相互相减" | 将 Q、K 各拆成两半，计算两张 Softmax 图，将第二张（按 lambda 缩放）从第一张中减去，再与 V 相乘 |
| 噪声基底 | "Softmax 的非零尾部" | Softmax 给每个无关 token 分配的 O(1/N) 权重，在长上下文下累加为 O(1) |
| lambda | "减法缩放因子" | 逐头可学习标量，参数化为 `exp(lq1·lk1) - exp(lq2·lk2) + lambda_init`；可取负值 |
| DIFF V1 | "ICLR 2025 版本" | 原始差分 Transformer；为保持参数量而将头维度减半，需要自定义算子，解码较慢 |
| DIFF V2 | "2026 年 1 月的修复版" | Q 头翻倍，KV 头不变；解码速度与基线持平，兼容 FlashAttention |
| 逐头 RMSNorm | "V1 的稳定器" | V1 在差分之后附加的归一化模块；V2 将其移除以避免训练后期不稳定 |
| 信噪比 | "多少注意力被浪费" | 真实信号位置上的权重与无关位置平均权重的比值 |
| 迷失中间 | "长上下文失效模式" | 经验现象：检索准确性在长上下文中间段落出现下降；DIFF 注意力能缓解该问题 |
| 算术强度 | "每加载一字节的浮点运算数" | V2 通过每次 KV 加载对应两倍查询而提升了这一比值；对内存受限的解码过程至关重要 |
